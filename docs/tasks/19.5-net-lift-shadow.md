# Phase 19.5: Net lift shadow

## Status

`Planned` — 설계만 있고 코드는 아직 없습니다.

Phase 19(Lighting and shadow)의 렌더러 묶음 기능 위에 얹는 작은 단계라 소수점 번호입니다. Phase 19가 먼저 들어와야 하지만, 이 단계의 결론은 Phase 19와 **반대**입니다 — 3D에서 기각한 `SceneEffect::DropShadow`가 여기서는 정답입니다.

## Objective

전개도에서 레이어를 잡아 돌릴 때 들리는 조각의 그림자를, 지금처럼 스티커마다 검은 사각형을 복제해 밀어 놓는 대신 **ThorVG의 `DropShadow` 효과 하나로** 그립니다. 가장자리가 부드러워지고, 그림자 사각형 생성이 지오메트리 코드에서 사라지고, 층(storey) 하나가 효과 하나가 됩니다.

Showcase로서의 의미는 Phase 19와 짝을 이룬다는 데 있습니다. 같은 효과를 3D에는 쓰지 않고 2D에는 쓰는 이유 — DropShadow는 화면 평면에서 실루엣을 밀어 놓는 그림자이고, 그것이 3D 바닥에는 맞지 않지만 "종이에서 들린 조각"에는 정확히 맞는다 — 를 한 저장소 안에서 보여 줍니다.

## 무엇이 이미 있고, 무엇이 걸리는가 (확인함)

### 넷 그림자는 스티커마다 복제한 사각형입니다

[`NetGeometry.cpp:671`](../../engine/src/graphics/NetGeometry.cpp)의 `raise`는 들린 조각을 `kNetLiftScale`만큼 키우고, 조각마다 `RenderFace`를 복제해 `(offset, offset)`으로 평행이동한 뒤 `Color{0, 0, 0, shade}`로 `scene.faces`에 먼저 넣습니다. 그림자를 조각보다 먼저, 층 단위로 넣어 "그림자는 아래 것에만 지고 자기 조각에는 지지 않는다"를 지킵니다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `kNetLiftCells` | 0.08 | 한 층당 그림자 거리(셀 단위) |
| `kNetLiftScale` | 0.035 | 한 층당 커지는 비율 |
| `kNetShadowAlpha` | 100 | 그림자 농도(opening 1일 때) |
| `kNetFaceStorey` / `kNetBandStorey` | 1 / 2 | 도는 면과 밴드 조각의 층 |

거리와 농도는 `ActiveRotation::opening`(0 내려놓음, 1 들림)을 따르고, opening은 각도가 아니라 **손이 잡고 있는지**에서 옵니다([`InteractionController::opening()`](../../engine/src/interaction/InteractionController.cpp)). 사람이 잡지 않은 회전(Player, scramble, 되감기)은 opening 0이라 그림자가 없습니다.

### 이것은 DropShadow의 모델 그대로입니다

ThorVG의 `Scene::add(SceneEffect::DropShadow, r, g, b, opacity, angle, distance, sigma, quality)`는 Scene의 알파 실루엣을 `angle` 방향으로 `distance`만큼 밀어 `sigma`로 흐린 뒤 원본 아래에 깔아 줍니다. 지금 코드가 손으로 하는 일(복제, 평행이동, 검은 반투명)에 블러가 더해진 것입니다.

각도 규약은 소스에서 확인했습니다([`tvgSwPostEffect.cpp:391`](../../../playground/thorvg/src/renderer/cpu_engine/tvgSwPostEffect.cpp)): `offset = (d·cos(90° − angle), −d·sin(90° − angle))`이므로 **0°가 위, 시계 방향으로 증가**하고, 지금의 `(+x, +y)` 오른쪽 아래는 **135°**입니다. offset은 정수 픽셀로 잘립니다 — opening이 120ms 동안 오르는 사이 그림자가 1px씩 계단으로 움직이는데, 최대 거리가 셀의 8%(셀 40px에서 3px)라 계단은 세 단 정도입니다.

### RenderScene에는 "묶음"이 없습니다

[`RenderScene.hpp`](../../engine/src/graphics/RenderScene.hpp)는 `underlays`, `faces`, `strokes`의 평평한 리스트입니다. DropShadow는 "이 면들을 하나로 보고 실루엣에 그림자를 달아라"는 선언이라 **묶음이 있어야 합니다.** Phase 19가 3D 그림자 Scene을 위해 같은 종류의 묶음을 렌더러에 만들므로, 이 단계는 그것을 재사용합니다. 이것이 19.5가 19 뒤에 오는 이유입니다.

### 계약 test는 opening 0의 회전을 봅니다

[`RenderContractTest.cpp:375`](../../tests/app/RenderContractTest.cpp)와 419행의 회전 중 test는 `turn_face`로 돌립니다. 사람이 잡은 회전이 아니라 opening이 0이고, 지금도 그 프레임에는 그림자 사각형이 없습니다(`shade == 0`이면 `continue`). 따라서 DropShadow 전환은 이 두 test의 픽셀을 바꾸지 않아야 합니다. 그래도 Step 3에서 확인합니다 — 들린 상태에서도 검사 지점(이동한 줄 바로 아래 셀 중앙)까지의 여유는 셀의 0.5이고 그림자 거리 0.08 + 블러 3σ ≈ 0.15로 닿지 않습니다.

### 링 다이어그램에는 들림 그림자가 없습니다

[`RingsGeometry.cpp`](../../engine/src/graphics/RingsGeometry.cpp)는 opening을 읽지 않습니다. 이 단계는 넷만 다룹니다.

## Architecture decisions

### 1. 묶음은 Phase 19의 것을 그대로 쓴다

```cpp
struct LiftShadow {        // ThorVG 타입 없음
    float dx, dy;          // 화면 픽셀
    std::uint8_t alpha;
    float sigma;
};

struct RenderGroup {
    std::vector<RenderFace> faces;
    std::optional<LiftShadow> shadow;
};
```

렌더러는 `RenderGroup`을 `tvg::Scene` 하나로 옮기고, `shadow`가 있으면 `(dx, dy)`를 `angle`과 `distance`로 바꿔 `DropShadow`를 겁니다. 그림자색은 검정, 불투명도는 `alpha`입니다. RenderScene은 여전히 ThorVG를 모릅니다 — 넘기는 것은 "이 묶음은 이만큼 들려 있다"입니다.

`RenderScene`에 `std::vector<RenderGroup> groups`가 생기고, 그리는 순서는 `underlays → faces → groups → strokes`입니다. 묶음은 항상 쉬는 면 위에 있습니다 — 들린 조각이 종이 위에 떠 있다는 뜻 그대로입니다.

### 2. 층 하나가 묶음 하나다

도는 면(`kNetFaceStorey`)과 밴드 조각(`kNetBandStorey`)은 들리는 높이가 달라 그림자 거리가 다릅니다. 그러므로 묶음은 둘이고, 낮은 층이 먼저 그려집니다. 지금 코드의 `raise(turning, 1); raise(band_pieces, 2);` 순서와 같습니다. 묶음 안에서는 조각끼리 그림자를 드리우지 않습니다 — Scene의 실루엣은 합집합이라, 붙어 있는 조각 사이에 그림자가 끼지 않고 이것이 지금 코드가 "shadows first within a storey"로 지키던 성질과 같습니다.

### 3. 방향은 고정이고, Phase 19의 광원과 무관하다

넷은 도식입니다. 그림자는 조명이 아니라 "들려 있다"는 신호이므로 방향은 지금처럼 오른쪽 아래(135°) 고정입니다. 3D 광원이 움직인다고 넷 그림자가 따라 돌면 도식이 흔들립니다. Phase 19와 공유하는 것은 광원이 아니라 렌더러의 묶음 기능뿐입니다.

### 4. 틈은 그림자에도 남는다

넷은 몸체 없는 스티커 도식이라 실루엣에 스티커 사이 틈이 있고, 그림자도 그 틈을 갖습니다. 지금도 그렇습니다. 블러가 틈을 부드럽게 만들어 지금보다 나아지고, 이것을 채우려 하지 않습니다 — 3D의 caster 분리 같은 것은 여기 필요 없습니다.

### 5. 지오메트리는 그림자를 모르게 된다

`raise`는 조각을 키우고 묶음에 넣고 `LiftShadow{offset, offset, shade, sigma}`를 적는 것으로 끝납니다. 그림자 사각형을 만들고 색을 정하고 순서를 맞추는 코드는 사라집니다. sigma는 새 상수 `kNetShadowSigmaCells` 하나(거리의 절반 정도)로 시작합니다.

## Scope

- `RenderScene::groups`와 `LiftShadow`(Phase 19가 만든 묶음이 있으면 그 타입에 필드 추가)
- `NetGeometry`의 `raise`를 묶음 출력으로 교체, 그림자 복제 제거
- 렌더러: 묶음 → `tvg::Scene` + `DropShadow`
- Phase 8 문서 개정 기록에 항목 추가
- Native test와 브라우저 확인

## Out of scope

- 링 다이어그램의 들림 표시
- 넷 그림자 방향을 3D 광원에 맞추는 것
- 3D 뷰에 DropShadow를 쓰는 것(Phase 19 결정 6)

## Implementation steps

### 1. 묶음 타입

- Phase 19의 렌더러 묶음에 `LiftShadow`를 얹거나, 없으면 `RenderGroup`을 만듭니다. `append_scene`이 `groups`도 옮기게 합니다.

### 2. NetGeometry

- `raise`가 `RenderGroup`을 냅니다. opening이 0이면 `shadow`는 비어 있고, 조각도 키우지 않습니다.
- Test([`NetTest.cpp`](../../tests/graphics/NetTest.cpp)): opening 0에서는 묶음이 없거나 그림자가 없고 `faces`만으로 지금과 같은 장면. opening 1에서 묶음 둘, 밴드 묶음의 거리가 면 묶음의 두 배. `faces`에 검은 사각형이 더는 없음.

### 3. 렌더러와 계약

- 묶음을 Scene으로 옮기고 DropShadow를 겁니다. `(dx, dy)` → `angle = atan2` 규약 변환은 렌더러 안의 함수 하나로 두고 test합니다(오른쪽 아래 → 135°).
- 회전 중 계약 test 두 개가 수정 없이 통과하는지 확인합니다. 사람이 잡은 회전을 브라우저에서 드래그해 그림자가 부드럽게 떨어지는지 봅니다.

### 4. 문서

- [Phase 8 문서](./08-net-rotation-and-interaction.md)의 개정 기록에 "그림자 사각형 → DropShadow" 항목을 추가하고 상수 표를 갱신합니다.
- 이 문서의 Status와 [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md).

## Acceptance criteria

- 넷에서 레이어를 잡고 돌리면 들린 조각 아래에 가장자리가 부드러운 그림자가 오른쪽 아래로 지고, 놓으면 사라집니다.
- 밴드 조각의 그림자가 도는 면의 그림자보다 멀리 떨어집니다.
- 사람이 잡지 않은 회전(scramble, 되감기, Player)에는 그림자가 없습니다 — 지금과 같습니다.
- `NetGeometry`가 내는 `faces`에 그림자 사각형이 없습니다.
- 회전 중 렌더 계약 test 두 개가 수정 없이 통과합니다.
- 링 다이어그램과 3D 뷰는 바뀌지 않습니다.

- **묶음의 위치를 `RenderScene`에 새 리스트로 둘지, `faces` 안에 섞을지.** 새 리스트가 "들린 것은 항상 쉬는 것 위"를 구조로 보장하므로 추천합니다. `faces`에 섞으면 순서를 지오메트리가 지켜야 하고 지금과 같은 부담이 남습니다.
